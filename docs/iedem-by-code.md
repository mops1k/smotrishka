# Авторизация по коду провайдера (iedem.tv)

Документ описывает, как приложение подключается к провайдеру **iedem.tv** по одному коду:
какие запросы уходят, что приходит в ответ, откуда берутся адреса каналов, программы передач
и архив. Все адреса и форматы ниже проверены на живом коде провайдера; сам код в документе
не приводится — это секрет пользователя.

## 1. Суть в одном абзаце

Пользователь вводит **только код** из личного кабинета iedem.tv (ключ доступа, 14 символов).
Приложение скачивает **общий каталог каналов** провайдера (он не зависит от кода), достаёт из
каждой ссылки идентификатор канала и собирает настоящую ссылку на поток по шаблону
`<хост провайдера>/iptv/<код>/<id канала>/index.m3u8`. Хост потоков уже зашит в приложение —
как в работающем JS-плеере провайдера, поэтому никаких CDN-полей пользователь не заполняет.

```
пользователь ──[код]──► приложение
                          │
                          ├─ GET /edem/edem_epg_ico.m3u8 ─────────► общий каталог каналов
                          │                                         (заглушки localhost + нули)
                          ├─ подстановка: <хост>/iptv/<код>/<id>/index.m3u8
                          │
                          ├─ GET <хост>/iptv/<код>/<id>/index.m3u8 ► HLS-плейлист канала
                          │
                          └─ GET x-tvg-url из каталога ────────────► программа передач (XMLTV)
```

## 2. Откуда известен механизм

Механизм не документирован провайдером, он восстановлен по работающему плееру и проверен
запросами:

| Источник | Что дал |
|---|---|
| `http://ottp.eu.org/prov/edem/prov.js` — профиль провайдера в JS-плеере | сборка ссылки канала: хост + `/iptv/` + ключ + `/` + id + `/index.m3u8`; адрес каталога |
| `http://ottp.eu.org/f/android/`, затем `stbPlayer/stbPlayer.js`, `stb/android/stb.js` | экран «Ввод кода провайдера»: код → `/d/<код>.js` (исполняемый профиль плеера, не данные) |
| `curl` к каталогу и к потоку | каталог отдаёт 200 и 3752 канала; поток отдаёт 200 и `application/x-mpegURL` |
| перехват трафика на устройстве (`adb reverse` + локальный HTTP-прокси) | фактические запросы приложения: домены, пути, кэш-бастер `?MMdd.HHmm` |

Важное следствие: «код провайдера» в JS-плеере — это **не** токен в адресе каталога.
`epg.drm-play.com/edem/edem_epg_ico<код>.m3u8` (ошибочная схема раннего плана) отдаёт `304`
с пустым телом на любой код, включая несуществующий, — это EPG-хостинг плеера, а не плейлист.

## 3. Запросы

| Назначение | Метод | Адрес | Ответ | Что берём |
|---|---|---|---|---|
| Каталог каналов | GET | `https://epg.ottp.eu.org/edem/edem_epg_ico.m3u8` | 200, M3U, ≈730 КБ, 3752 канала | названия, группы, логотипы, `tvg-id`, `tvg-rec`, id канала из ссылки, `x-tvg-url` |
| Поток канала | GET | `http://<хост провайдера>/iptv/<код>/<id>/index.m3u8` | 200, `application/x-mpegURL` | HLS-плейлист (сегменты `.ts` с подписью `md5`) |
| Архив передачи | GET | та же ссылка + `?utc=<начало>&lutc=<сейчас>` | 200, HLS | проигрывание передачи с начала |
| Программа передач | GET | значение `x-tvg-url` каталога (`http://epg.one/epg.xml.gz`) | 200, gzip + XMLTV | сетка передач |

Хост провайдера (в приложении — константа):

```
http://sewv654wfcsdwfi87fwvgbngh.siauliairsavlt.pw
```

**Важно про http.** Каталог отдаётся и по https, а поток канала и программа передач
(`http://epg.one/…`) — только по http. Android с `targetSdk 36` по умолчанию блокирует
незашифрованный трафик, поэтому в манифесте стоит `android:usesCleartextTraffic="true"`:
без этого приложение получает «нет связи», хотя тот же адрес открывается в браузере
телефона. Для IPTV это норма: провайдеры массово отдают потоки по http.

Кэш-бастер `?MMdd.HHmm` (например `?0319.1812`) — версия сборки плеера; для наших запросов
не нужен.

## 4. Каталог каналов: что внутри

Файл — обычный M3U, который разбирает наш парсер. Реальные строки (срез каталога):

```m3u
#EXTM3U x-tvg-url="http://epg.one/epg.xml.gz"
#EXTINF:0 group-title="новости" tvg-id="146" tvg-logo="http://epg.one/img/146.png" tvg-rec="0",Первый канал UHD
http://localhost/iptv/00000000000000/19241/index.m3u8
```

Разбор заглушки:

| Часть заглушки | Значение | Откуда берётся настоящее |
|---|---|---|
| `localhost` | хост-заполнитель | константа приложения (хост провайдера) |
| `00000000000000` | 14 нулей — место ключа | код пользователя |
| `19241` | id канала | не меняется |
| `/iptv/` и `/index.m3u8` | путь и файл плейлиста | не меняются |

Итог для канала `19241` и кода `<код>`:

```
http://sewv654wfcsdwfi87fwvgbngh.siauliairsavlt.pw/iptv/<код>/19241/index.m3u8
```

## 5. Алгоритм подстановки

1. Код обрезается по краям и проверяется: непустой, без пробелов и слэшей (иначе — ошибка
   без запроса в сеть).
2. Скачивается каталог `http://epg.ottp.eu.org/edem/edem_epg_ico.m3u8`.
3. Каталог разбирается обычным M3U-парсером (BOM, UTF-8 → cp1251, группы, логотипы, архив).
4. Для каждого канала из его ссылки извлекается id: путь разбивается на сегменты, нужен
   сегмент `iptv` и последний сегмент с расширением `.m3u8`; id — предпоследний сегмент.
5. Ссылка канала заменяется на `<хост>/iptv/<код>/<id>/index.m3u8`.
6. Канал, из ссылки которого id не извлекается, **остаётся с исходной ссылкой**: лучше показать
   канал, чем потерять его из каталога.
7. `x-tvg-url` сохраняется как адрес программы передач, `tvg-rec` — как доступность архива.

## 6. Поток и архив

Поток — обычный HLS: ответ содержит `#EXTM3U`, `#EXT-X-VERSION`, `#EXT-X-MEDIA-SEQUENCE`
и ссылки на сегменты вида `http://50.7.144.98/iptv/<код>/<id>/<время>.ts?md5=<подпись>`.
Сегменты уже подписаны сервером, приложению ничего подписывать не нужно.

Архив строится добавлением двух параметров к ссылке канала:

```
<ссылка канала>?utc=<начало передачи, секунды UNIX>&lutc=<текущее время, секунды UNIX>
```

Так это делает профиль провайдера в плеере: `?utc=` + начало, `&lutc=` + `Date.now()/1000`.

## 7. Программа передач

Адрес берётся из заголовка каталога: `x-tvg-url="http://epg.one/epg.xml.gz"`. Файл сжат gzip
(признак — байты `1f 8b`), внутри XMLTV. Наш парсер уже умеет и то и другое: качает байты,
определяет gzip по магии, читает потоком, сопоставляет каналы по `tvg-id` каталога и `channel`
из XMLTV.

## 8. Сообщения об ошибках

| Ситуация | Текст для пользователя |
|---|---|
| Код пустой | «Введите код из личного кабинета iedem.tv» |
| Код содержит пробел или слэш | «Код не должен содержать пробелов и слэшей» |
| Сервер ответил не 2xx | «Код не подошёл или iedem.tv недоступен (ответ N)» |
| Нет сети | «Нет связи с iedem.tv: проверьте сеть на устройстве» |
| Пустое тело ответа | «iedem.tv вернул пустой список каналов — проверьте код» |

## 9. Что зашито в приложение и где менять

| Что | Значение | Файл |
|---|---|---|
| База каталога | `http://epg.ottp.eu.org` | `IedemProvider.DEFAULT_CHANNEL_LIST_BASE` |
| Путь каталога | `/edem/edem_epg_ico.m3u8` | `IedemProvider.PLAYLIST_PATH` |
| База потоков | `http://sewv654wfcsdwfi87fwvgbngh.siauliairsavlt.pw` | `IedemProvider.DEFAULT_STREAM_BASE` |
| Путь потока | `/iptv/<код>/<id>/index.m3u8` | `IedemProvider.STREAM_PATH` |
| Правило id канала | сегмент `iptv` + `.m3u8` | `IedemProvider.channelIdOf` |

Файлы реализации: `core/data/.../IedemProvider.kt`, `IedemPlaylistLoader.kt`,
`IedemCodeResult.kt`; код в модели — `PlaylistSource.IedemCode`; в UI пункт называется
**«Код iedem.tv»**.

Если провайдер сменит хост потоков, правится одна константа — код пользователя и каталог
не меняются.

## 10. Чего приложение не делает

- Не скачивает `/d/<код>.js`: в JS-плеере это исполняемый профиль провайдера, а не данные.
- Не требует «ссылки на канал» (CDN-хост): в нашей реализации хост зашит.
- Не поддерживает VPortal и медиатеку провайдера — это отдельные возможности плеера.

## 11. Как проверить руками

```bash
# каталог: 200 и M3U, первая строка — #EXTM3U x-tvg-url=…
curl -sS -o catalog.m3u -w '%{http_code} %{size_download}\n' \
  http://epg.ottp.eu.org/edem/edem_epg_ico.m3u8

# внутри — заглушки с localhost и нулями
grep -m3 '^http' catalog.m3u

# поток по коду: ожидаем 200 и application/x-mpegURL
curl -sS -D - -o stream.m3u8 \
  'http://sewv654wfcsdwfi87fwvgbngh.siauliairsavlt.pw/iptv/<КОД>/19241/index.m3u8' | head -3
head -3 stream.m3u8
```

Признак успеха: `content-type: application/x-mpegURL` и тело с `#EXTM3U` / `#EXTINF`.

## 12. Риски и ограничения

- **Хост может смениться.** Он не документирован и живёт в профиле плеера; при смене поток
  перестанет отвечать, а каталог продолжит работать. Лечится правкой константы.
- **Формат каталога не гарантирован.** Если провайдер перестанет класть в каталог `iptv`-ссылки
  с id, подстановка перестанет срабатывать — каналы останутся с заглушками.
- **Код — секрет.** В базе он не хранится: только описание источника; сам код лежит
  в зашифрованном виде (AES-GCM, ключ в Android Keystore).
- **Права.** Механизм восстановлен для доступа к собственной подписке пользователя
  (совместимость), код плеера не копируется.
