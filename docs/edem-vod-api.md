# HTTP API медиатеки VPortal: полный справочник

Справочник по HTTP-API медиатеки провайдера iedem.tv (движок **VPortal**, тип ответа
`videoportal`). Дополняет [edem-vod.md](edem-vod.md): там — короткий контракт, которым
пользуется приложение, здесь — полное описание всех проверенных команд, полей, краевых
случаев и ограничений, включая то, что клиент пока не использует.

Всё ниже проверено живыми запросами **10.11.2026** (10:55–11:15 UTC) на личном портале
Александра по адресу `http://<портал>/api/v1/`. Адрес, хеш хоста и ключ в документ не
переносятся: вместо них `<портал>`, `<потоковый хост>`, `<ключ>`. Обоснование каждого
утверждения — в разделе [10. Журнал проверок](#10-журнал-проверок).

---

## 1. Обзор

- API — единственная точка входа в медиатеку: один URL вида `http://<портал>/api/v1/`,
  один метод `POST`, тело — JSON-объект с полем `key` и командой `cmd`.
- Ответ — JSON. Успех и отказ приходят с кодом `200`; различаются по полю `type`:
  `"error"` — отказ, всё остальное — данные.
- Модель навигации **серверная**: сервер сам кладёт в ответ элементы `request` — готовые
  тела следующих запросов (у категории, у маркера страницы, у фильтра). Клиенту не нужно
  знать параметры, достаточно подмешать `key`; приложение, впрочем, собирает запросы
  само по известной схеме.
- Типы верхнеуровневых ответов: `videoportal` (корень), `category` (каталог и поиск),
  `stream` (карточка фильма/серии), `multistream` (сезон/сборник), `error`.
- Данные: ~13,1 тыс. фильмов, 4,8 тыс. сериалов и ещё семь категорий; постеры —
  JPEG на том же хосте, видео — HLS на отдельном потоковом хосте.
- API приватное и недокументированное: ни схемы, ни версии, ни changelog. Разбор на
  клиенте обязан быть терпимым (неизвестные поля игнорировать, отсутствующие — не ронять экран).
- Запросы только на чтение: ни одна проверенная команда не меняет состояние на сервере
  (истории, избранного, закладок нет — см. раздел 8).

## 2. Авторизация и подключение

### 2.1 Что выдаёт личный кабинет

Одна строка подключения:

```
portal::[key:<ключ>]http://<портал>/api/v1/
```

| Часть | Вид | Секрет | Смысл |
|---|---|---|---|
| префикс | `portal::` | нет | тип подключения |
| ключ | `[key:<ключ>]`, формат `16 hex - 16 hex` | **да** | авторизация всех запросов |
| адрес | `http://<портал>/api/v1/` | нет | эндпоинт портала, обязательно со `/` на конце |

### 2.2 Как передаётся ключ

- Только **в теле** запроса, полем `key` верхнего уровня. Порядок полей не важен.
- В query-строке (`?key=…`) ключ **не принимается** — ответ `subscription required`.
- Ключ подмешивается в **каждый** запрос, включая те, что сервер прислал в `request`
  (сервер их без ключа не принимает).
- Дубликат поля `key` в теле: побеждает **первый** (`{"key":"плохой","key":"<ключ>",…}`
  → `subscription required`), то есть тело разбирается нестандартно — не полагаться на JSON-парсер.
- Ни `Authorization`, ни cookie, ни `User-Agent` не нужны и на доступ не влияют.

### 2.3 Проверка подключения

Корневой запрос (раздел 4.1). Успех — объект с `type: "videoportal"`; отказ —
`{"type":"error","description":"subscription required"}`. Других способов проверить
подписку API не даёт (команд `info`, `subscription`, `account` нет — раздел 4.5).

### 2.4 Ошибки доступа

| Ситуация | Ответ |
|---|---|
| `key` отсутствует | `200` + `subscription required` |
| `key` пустой (`""`) | `200` + `subscription required` |
| `key` = `null` | `200` + `subscription required` |
| `key` чужой/неверный | `200` + `subscription required` |
| `key` в query, а не в теле | `200` + `subscription required` |
| тело не JSON / JSON-массив / `{}` | `200` + `subscription required` (не `400`!) |
| подписка кончилась | `200` + `subscription required` (предположительно; отдельной проверки нет) |

Различить «нет ключа», «ключ неверный» и «подписка кончилась» API не позволяет — текст
один и тот же.

## 3. Общие правила

### 3.1 Метод и путь

| Проверка | Результат |
|---|---|
| `POST /api/v1/` | `200`, JSON |
| `GET /api/v1/` | `405 Method Not Allowed`, тело пустое (`Content-Length: 0`) |
| `HEAD /api/v1/` | `405` |
| `OPTIONS /api/v1/` | `204 No Content`, CORS-заголовки, `Access-Control-Max-Age: 600` |
| `POST /api/v1` (без `/` на конце) | `500`, HTML-страница nginx |
| `POST /api/`, `POST /`, `POST /api/v2/` | `404`, HTML-страница nginx |
| `POST /api/v1/foo/bar`, `/api/v1/index.php`, `/api/v1//` | `200` — путь сверяется по префиксу `/api/v1/` |
| `POST /API/V1/` | `404` — регистрозависимо |

Вывод: адрес нужно нормализовать ровно к `…/api/v1/` (со слэшем на конце), иначе `500`.

### 3.2 Заголовки запроса

| Заголовок | Обязателен | Поведение |
|---|---|---|
| `Content-Type: application/json` | номинально да | без заголовка (curl подставляет `application/x-www-form-urlencoded`) сервер отвечает `200`; с явным `text/plain` — `400` с пустым телом |
| `Accept-Encoding: gzip, deflate` | нет | ответ приходит `Content-Encoding: gzip` и корректно распаковывается; `deflate` не проверялся |
| `User-Agent`, `Referer`, `Origin`, cookie | нет | на API не влияют |

Ответ API:

```
HTTP/1.1 200 OK
Server: nginx
Content-Type: application/json
Transfer-Encoding: chunked        (или Content-Length для мелких ответов)
Connection: keep-alive
Access-Control-Allow-Origin: *
Access-Control-Allow-Credentials: true
```

Кодировка — UTF-8 без `charset` в заголовке. Кириллица в JSON отдаётся как есть
(`ensure_ascii` не применяется), в запросе допустима и escaped-форма `\uXXXX`.

### 3.3 Коды ответов

| Код | Когда | Тело |
|---|---|---|
| `200` | любой разобранный запрос, включая логические ошибки | JSON |
| `204` | `OPTIONS` | пусто |
| `400` | пустое тело POST; `Content-Type: text/plain` | пусто |
| `404` | путь вне `/api/v1/` | HTML nginx |
| `405` | `GET`, `HEAD` | пусто |
| `413` | тело запроса больше **1024 байт** | HTML nginx «413 Request Entity Too Large» |
| `500` | путь `/api/v1` без завершающего слэша | HTML nginx |

Кэширования у API нет: ни `Cache-Control`, ни `ETag`, ни `Last-Modified`, `304` не
поддерживается — ответ всегда полный. `keep-alive` работает (повторный запрос по тому же
соединению: `connect=0`).

### 3.4 Формат ошибок

```json
{"type": "error", "description": "subscription required"}
```

```json
{"type": "error", "description": "illegal command"}
```

Тело маленькое (55–56 байт), `description` — единственное осмысленное поле. Других
значений `description` за ~120 запросов не встретилось.

### 3.5 Пагинация каталога

Курсорная, через служебный элемент в конце массива `items`:

```json
{"type": "next", "title": "next", "request": {"offset": 30, "limit": 0}}
```

- `request.offset` = `offset + фактический limit`; `request.limit` всегда `0`
  (то есть «серверный размер по умолчанию»), свой `limit` нужно подставлять самому.
- Маркер есть, только если за текущей страницей остались элементы. На последней странице
  его нет — это и есть признак конца.
- Маркер входит в длину массива: страница `limit=30` → **31** элемент (`30 + next`),
  `limit=300` → 301.
- `count` в ответе каталога — общее число карточек в категории и не зависит от страницы.
- Поиск пагинации не имеет вовсе (раздел 4.4).

### 3.6 Лимиты

| Что | Значение | Проверено |
|---|---|---|
| тело запроса | **1024 байта** (1024 — ок, 1025 — `413`) | паддинг-полем и длинным `query` |
| страница каталога по умолчанию | **30** элементов | `limit` отсутствует, `0`, `-1`, `"abc"` → 30 |
| максимум страницы | **300** элементов | `limit=300` → 300 + next; `301`, `500`, `5000` → те же 300 |
| результатов поиска | до **500** (наблюдались срезы 200/100/24 по коротким запросам) | `the` → 500, `a`/`e`/`s`/`я`/`о` → 200, `1` → 100, `12` → 24 |
| rate limit | не обнаружен | 30 последовательных запросов: все `200`, 357–696 мс |

### 3.7 Тайминги (одна и та же сеть, 10.11.2026)

| Запрос | Время |
|---|---|
| корень (10 категорий, ~8 КБ) | 95–150 мс |
| страница 30 элементов (~32 КБ) | 100–180 мс |
| страница 300 элементов (~330 КБ) | 300–750 мс |
| карточка (~1–2,5 КБ) | ~100 мс |
| серия запросов подряд (30 шт.) | 357–696 мс на запрос (растёт под нагрузкой) |

## 4. Эндпоинты

Все команды передаются в поле `cmd`. Команды без `cmd` (пустой объект, `cmd: ""`,
`cmd: null`, `cmd: 123`) трактуются как корневой запрос.

### 4.1 Корневой запрос — категории и элементы управления

Назначение: список категорий медиатеки + шаблоны поиска и фильтров; одновременно проверка
подключения.

**Запрос**

```json
{"key": "<ключ>"}
```

Допустимо `{}` (плюс ключ), `{"key":"<ключ>","cmd":""}` и т.п.

**Ответ** (`200`, ~8 КБ)

```json
{
  "type": "videoportal",
  "url": "http://<портал>/api/v1/",
  "request": {"key": "<ключ>"},
  "items": [
    {"type": "category", "title": "фильмы",
     "request": {"cmd": "flicks", "fid": 1, "offset": 0, "limit": 0}},
    {"type": "category", "title": "Сериалы Турции",
     "request": {"cmd": "flicks", "fid": 11, "offset": 0, "limit": 0, "vc": 1}}
  ],
  "controls": {
    "search": {"request": {"cmd": "search", "query": "{USERINPUT}"}},
    "filters": [
      {"type": "enum", "title": "Год", "items": [
        {"title": "2026", "request": {"filter": "on", "years": "2026"}}]},
      {"type": "enum", "title": "Жанр", "items": [
        {"title": "биография", "request": {"filter": "on", "genre": 1}}]}
    ]
  }
}
```

**Поля ответа**

| Поле | Тип | Смысл |
|---|---|---|
| `type` | string | всегда `"videoportal"` |
| `url` | string | адрес портала, с которого отвечали (эхо) |
| `request` | object | эхо запроса: только `{"key": …}`, без `cmd` |
| `items` | array | категории (всегда 10 элементов) |
| `controls` | object | шаблоны поиска и фильтров |

**Элемент `items[]` (категория)**

| Поле | Тип | Смысл |
|---|---|---|
| `type` | string | `"category"` |
| `title` | string | название для пользователя |
| `request` | object | готовое тело запроса каталога: `cmd`, `fid`, `offset`, `limit`, иногда `vc` |
| `request.vc` | number, опционально | флаг «вертикального» каталога; **обязателен** для категорий `vc:1` (см. ниже) |

Состав корня (порядок серверный, `count` в корне не отдаётся):

| `fid` | Название | `count` (проверен отдельно) | Примечание |
|---|---|---|---|
| 1 | фильмы | 13121 | |
| 2 | сериалы | 4841 | |
| 11 | Сериалы Турции | 116 | в `request` приходит `vc: 1` |
| 3 | мультфильмы | 1587 | |
| 4 | мультсериалы | 815 | |
| 5 | 3D | 74 | |
| 6 | Телепередачи | 1564 | |
| 7 | Аниме | 55 | |
| 8 | Спорт | 104 | |
| 10 | С наступающим! | 80 | в `request` приходит `vc: 1` |

**`controls.search`** — шаблон поиска: `request` содержит `cmd: "search"` и
`query: "{USERINPUT}"`; подставляется запрос пользователя, ключ добавляется клиентом.

**`controls.filters`** — два `enum`-фильтра: «Год» (81 элемент: диапазоны `2021-2026`,
`2016-2021`, `2011-2016`, `2006-2011` и отдельные годы 2026…1985) и «Жанр» (27 элементов:
`genre` 1–27, например 1 — биография, 2 — боевик, 3 — вестерны). Каждый элемент —
`{"title": …, "request": {"filter": "on", "years": "…"}}` либо
`{"filter": "on", "genre": N}`.

> **Фильтры не работают.** Сервер их принимает, но игнорирует: `count` и порядок не
> меняются ни для одного из вариантов (проверено: `years`, `genre`, оба вместе, с
> `filter`/без, `limit 0` и `limit 3`). См. раздел 7.

### 4.2 `flicks` — каталог категории

Назначение: постраничный список карточек категории.

**Запрос**

```json
{"key": "<ключ>", "cmd": "flicks", "fid": 1, "offset": 0, "limit": 30}
```

| Поле | Тип | Обязательно | Смысл |
|---|---|---|---|
| `cmd` | string | да | `"flicks"` |
| `fid` | number | да | идентификатор категории; **только числом** |
| `offset` | number | нет (0) | смещение от начала, с 0 |
| `limit` | number | нет (30) | размер страницы, максимум 300 |
| `vc` | number | для `fid` 10 и 11 | без него категория пуста |
| прочие | любые | нет | игнорируются |

**Ответ**

```json
{
  "type": "category",
  "items": [
    {"type": "stream", "title": "Горькое Рождество",
     "img": "http://<портал>/posters/h/p_00025377.jpg",
     "imglr": "http://<портал>/posters/l/p_00025377.jpg",
     "request": {"cmd": "flick", "fid": 147713},
     "fid": 147713,
     "url": "http://<потоковый хост>/vod/<ключ>/S30/00025377/0/master.m3u8",
     "fhd": false, "4k": false, "hdr": false,
     "year": 2026, "duration": 112, "description": "…", "agelimit": 0},
    {"type": "next", "title": "next", "request": {"offset": 30, "limit": 0}}
  ],
  "count": 13121
}
```

**Поля ответа**

| Поле | Тип | Смысл |
|---|---|---|
| `type` | string | всегда `"category"` |
| `items` | array | карточки + опциональный маркер `next` |
| `count` | number | всего карточек в категории |

**Поля элемента списка**

| Поле | Тип | Есть у | Смысл |
|---|---|---|---|
| `type` | string | всех | `"stream"` (фильм с готовым `url`), `"multistream"` (сезон/сборник — нужен `flick`), `"next"` (маркер страницы) |
| `title` | string | всех | название; у сезонов — «… Сезон N.», у сборников — своё |
| `img` | string | stream/multistream | постер 500×750, JPEG ~50 КБ |
| `imglr` | string | stream/multistream | превью 400×600, JPEG ~21 КБ (для сетки) |
| `request` | object | всех | готовый запрос карточки: `{"cmd":"flick","fid":N}` |
| `fid` | number | stream/multistream | идентификатор карточки (у `next` отсутствует) |
| `url` | string | **только stream** | готовая HLS-ссылка на `master.m3u8`; у `multistream` в списке `url` нет |
| `fhd` | bool | stream/multistream | есть вариант Full HD |
| `4k` | bool | stream/multistream | есть 4K |
| `hdr` | bool | stream/multistream | есть HDR |
| `year` | number | stream/multistream | год выпуска |
| `duration` | number | stream/multistream | длительность в секундах; `0` — неизвестна (у сезонов почти всегда `0`) |
| `description` | string | stream/multistream | описание (приходит сразу, отдельный запрос за текстом не нужен) |
| `agelimit` | number | stream/multistream | возрастной лимит: `0` (нет) или `18` (взрослые категории) |

Наблюдения по составу: в категориях-сериалах (`fid` 2, 4, 11) у элементов нет `url`
(только `multistream`), в смешанных категориях (6, 8) `url` встречается у части элементов.
Набор полей в категории одинаковый, кроме `url`.

**Порядок** — серверный, «новые сверху» по внутреннему id с редкими вкраплениями старых
(в первой сотне категории 1 годы 2026/2025 с единичными 1984). Повторные запросы той же
страницы дают тот же порядок — сортировка стабильна. Параметры сортировки
(`sort`, `order`, `by`, `sort=1`, `new`) игнорируются.

**Краевые случаи `flicks`**

| Запрос | Ответ |
|---|---|
| `limit` отсутствует / `0` / `-1` / `"abc"` | страница 30 элементов (серверный размер) |
| `limit` = 299 | 299 элементов + `next` (300 в массиве) |
| `limit` = 300 | 300 + `next` (301) |
| `limit` = 301/500/5000 | всё равно 300 + `next` (жёсткий потолок) |
| `offset` = 13118 (`count`=13121) | 3 элемента, `next` нет |
| `offset` = `count` или больше | `{"type":"category","items":[],"count":13121}` — валидно, пусто |
| `offset` = `"abc"` | как `offset 0` |
| `offset` = **отрицательный** (`-1`, `-2`, `-30`, `-100`) | **невалидный JSON**: `"items":[,{…"next"…}]` — лишняя запятая, парсер обязан это пережить |
| `fid` = `"1"` (строкой), `"abc"`, `null`, отсутствует, `0`, `1.0` (дробное), `99999` | `{"type":"category","items":[],"count":0}` — без ошибки |
| `fid` = 10 или 11 без `vc` | `items: []`, `count: 0` |
| `fid` = 10 или 11 с `vc: 1` | нормальный список (80 и 116) |
| `fid` = 9, 20, 30, 40 (нет в корне) | категории существуют: 444, 1, 4, 4 (раздел 7.3) |
| `vc` = 2, 3 | пусто (`count: 0`) |
| `filter`, `years`, `genre`, `year`, `country`, `quality`, `hd`, `only4k`, `search`, `query` | полностью игнорируются |

Ответ каталога **не содержит** `controls`, `request`, `url` (кроме `url` в элементах).

### 4.3 `flick` — карточка

Назначение: детали фильма (готовый поток) либо список серий сезона.

**Запрос**

```json
{"key": "<ключ>", "cmd": "flick", "fid": 147573}
```

| Поле | Тип | Обязательно | Смысл |
|---|---|---|---|
| `cmd` | string | да | `"flick"` |
| `fid` | number | да | идентификатор карточки; только числом |

**Ответ: одиночный фильм** (`type: "stream"`, ~0,9 КБ)

```json
{
  "type": "stream",
  "title": "Одиссея (EN)",
  "img": "http://<портал>/posters/h/p_00025355.jpg",
  "imglr": "http://<портал>/posters/l/p_00025355.jpg",
  "fid": 147573,
  "pfid": 0,
  "variants": {"2160": "http://<потоковый хост>/vod/<ключ>/S30/00025355/0/index1.m3u8"},
  "url": "http://<потоковый хост>/vod/<ключ>/S30/00025355/0/master.m3u8",
  "fhd": false, "4k": true, "hdr": false,
  "year": 2026, "duration": 173,
  "description": "…",
  "agelimit": 0
}
```

| Поле | Тип | Смысл |
|---|---|---|
| `type` | string | `"stream"` — одиночный поток |
| `title` | string | название |
| `img`, `imglr` | string | постер и превью (адреса те же, что в списке) |
| `fid` | number | идентификатор карточки |
| `pfid` | number | родитель: `0` у самостоятельного фильма, `fid` сезона у серии |
| `url` | string | HLS `master.m3u8` — основной адрес воспроизведения |
| `variants` | object | варианты качества: ключ — качество (`"480"`, `"720"`, `"1080"`, `"1440"`, `"2160"`, `"auto"`), значение — адрес плейлиста (`indexN.m3u8`; `auto` → тот же `master.m3u8`) |
| `fhd`, `4k`, `hdr` | bool | метки качества |
| `year` | number | год |
| `duration` | number | длительность, секунды |
| `description` | string | описание |
| `agelimit` | number | возрастной лимит |

Наблюдения по `variants` (111 карточек): встречались наборы `{480,720,1080,auto}`,
`{720,1080,2160,auto}`, `{2160}` (только 4K), `{480}` (архив). Внутри набора индексы
`indexN` идут по порядку качества (`480`→`index1`, `720`→`index2`, `1080`→`index3`), но
нумерация зависит от набора, поэтому **строить ссылку на качество по индексу нельзя** —
только брать значение из `variants`.

**Ответ: сезон/сборник** (`type: "multistream"`, 1,4–2,3 КБ)

```json
{
  "type": "multistream",
  "title": "Томми и Таппенс. Сезон 1.",
  "items": [
    {"type": "stream", "title": "Серия 1",
     "request": {"cmd": "flick", "fid": 147674},
     "fid": 147674,
     "url": "http://<потоковый хост>/vod/<ключ>/S30/00025370/0/master.m3u8",
     "fhd": true, "4k": false, "hdr": false},
    {"type": "stream", "title": "Серия 2",
     "request": {"cmd": "flick", "fid": 147675},
     "fid": 147675,
     "url": "http://<потоковый хост>/vod/<ключ>/S30/00025370/1/master.m3u8",
     "fhd": true, "4k": false, "hdr": false}
  ],
  "img": "http://<портал>/posters/h/p_00025370.jpg",
  "imglr": "http://<портал>/posters/l/p_00025370.jpg",
  "fid": 147673,
  "fhd": true, "4k": false, "hdr": false,
  "year": 2026, "duration": 0,
  "description": "…", "agelimit": 0
}
```

| Поле | Тип | Смысл |
|---|---|---|
| `type` | string | `"multistream"` |
| `title` | string | название сезона/сборника |
| `items` | array | дочерние потоки: серии, части, варианты |
| `items[].type` | string | всегда `"stream"` |
| `items[].title` | string | подпись: «Серия N», «Часть N», «N», «1/4», произвольная («200. Каша.avi») |
| `items[].fid` | number | идентификатор серии/части |
| `items[].request` | object | готовый запрос деталей: `{"cmd":"flick","fid":<серия>}` |
| `items[].url` | string | **готовый `master.m3u8` серии** — можно играть сразу, без второго запроса |
| `items[].fhd` / `4k` / `hdr` | bool | метки качества серии |
| `img`, `imglr`, `fid`, `fhd`, `4k`, `hdr`, `year`, `duration`, `description`, `agelimit` | — | как у фильма, но общие на весь сезон |

Ограничения дочерних элементов: нет `img`/`imglr` (постер один на сезон), нет `variants`,
нет `duration`, нет `year`/`description`. Ссылка на конкретную серию берётся из её `url`
или из `variants` после запроса карточки серии.

**Ответ: детали серии** (`flick` по `fid` серии)

```json
{
  "type": "stream",
  "title": "Серия 1",
  "fid": 147674,
  "pfid": 147673,
  "variants": {
    "480": "http://<потоковый хост>/vod/<ключ>/S30/00025370/0/index1.m3u8",
    "720": "…/index2.m3u8",
    "1080": "…/index3.m3u8",
    "auto": "…/master.m3u8"
  },
  "url": "…/master.m3u8",
  "fhd": true, "4k": false, "hdr": false
}
```

Здесь появляются `variants` и `pfid` (родительский сезон), но **нет** `img`, `imglr`,
`year`, `description`, `duration`. Чтобы показать экран серии, клиенту нужны данные
сезона или списка.

**Сезоны.** Отдельного уровня «сезон» нет: каждый сезон — самостоятельная карточка в
каталоге («… Сезон 1.», «… Сезон 7.»), вложенных сезонов не бывает. Дочерние элементы
могут быть не сериями: в категориях 6 и 8 встречаются «Часть 1/2/3», «1 день + открытие»,
«BBC: … 1/4», названия файлов и просто числа — эвристика «начинается с „Серия“»
ненадёжна. В категории 1 у фильма может быть 2 дочерних элемента («Дом. История
путешествия» + «Серия 2»), то есть `multistream` — это «несколько потоков», а не строго сезон.

**Краевые случаи `flick`**

| Запрос | Ответ |
|---|---|
| `fid` = существующей карточки | объект `stream`/`multistream` |
| `fid` = 99999, `fid` = 1 (id категории) | `{}` — пустой объект, `200` |
| `fid` отсутствует, `0`, `"147573"` (строкой), `null` | **карточка постороннего фильма** — `fid 60`, «Три дня до весны» (не ошибка!) |
| `fid` = `147573.9` (дробное) | та же подстановка по умолчанию |
| `fid` = `-5` | `{}` — пустой объект |
| лишние поля (`quality`, `offset`, `limit`) | игнорируются |

Вывод для клиента: никогда не отправлять `flick` без числового `fid` — вместо ошибки
придёт чужая карточка.

### 4.4 `search` — поиск

Назначение: поиск по названиям.

**Запрос**

```json
{"key": "<ключ>", "cmd": "search", "query": "матрица", "offset": 0}
```

| Поле | Тип | Обязательно | Смысл |
|---|---|---|---|
| `cmd` | string | да | `"search"` |
| `query` | string | да | строка поиска |
| `offset` | number | нет | **игнорируется** |
| `limit` | number | нет | **игнорируется** |
| `fid` | number | нет | **игнорируется** (выдача не сужается) |

**Ответ**

```json
{"type": "category", "items": [ {…элемент списка, как в 4.2…} ]}
```

Ключей всего два: `type` и `items`. **Нет** `count`, **нет** маркера `next` — узнать
общее число попаданий и догрузить следующую страницу через API нельзя.

**Семантика (проверено)**

| Свойство | Поведение | Пример |
|---|---|---|
| регистр | не важен | `матрица` = `Матрица` = `МАТРИЦА` |
| частичное совпадение | да, подстрока | `матриц` → те же 8 |
| ё/е | склеиваются | `звёзд` = `звезд` (184), `ёж` = `еж` = `ЁЖ` (284) |
| пробелы по краям | обрезаются | `" матрица "` = `матрица` |
| пустой/пробельный `query` | `items: []` | `""`, `"   "` |
| поиск по `fid` | не работает | `"147704"` → 0 |
| языки | русские названия **и оригинальные английские** | `matrix` → 6 (Матрица…), `odyssey` → 6 |
| описание | **не ищется** | `Пенелопе` (слово из описания «Одиссеи») → 0, `Лансароте` → 0 |
| несколько слов | все слова должны присутствовать **в прямом порядке** | `матрица перезагрузка` → 2, `перезагрузка матрица` → 0 |
| спецсимволы | не шаблоны: `*`, `%`, `_`, `"`, `+`, `&`, `#`, `?`, `\` → 0 совпадений | `матрица*` → 0 |
| годы | находятся как отдельные токены | `1999` → 143, `1984` → 77, `2026` → 500 (потолок) |
| слово + год | вместе не ищутся | `матрица 1999` → 0 |
| очень длинный `query` | тело > 1024 байт → `413` nginx | 1024 байта — ок, 1025 — отказ |
| пагинация | **не работает** | `offset` 0/30/490/500/5000 → одинаковые 500 и тот же первый элемент |
| `limit` | не работает | `limit 2`/`60`/`1000` → те же 8/500 |

Потолок выдачи: 500 для обычных запросов; для односимвольных запросов наблюдались ровно
200 (`a`, `e`, `s`, `я`, `о`), для `1` — 100, для `12` — 24. Практический вывод: показывать
«найдено N» по длине массива нельзя, а догрузку «показать ещё» реализовать нечем.

**Порядок выдачи** — серверный (по внутреннему индексу), не по алфавиту и не по году;
для `матрица` первым идёт «Матрица 2: Перезагрузка [HDR]» (2003).

## 5. Стриминг

### 5.1 Как получить поток

1. `flicks` → элемент списка: у `type: "stream"` уже есть `url`, у `multistream` — только `fid`.
2. `flick` по `fid` → `url` (master) + `variants` (по качествам) для фильма; для сезона —
   `items[].url` у каждой серии.
3. Плеер открывает `master.m3u8` или конкретный `indexN.m3u8` из `variants`.

Схема адреса:

```
http://<потоковый хост>/vod/<ключ>/S<NN>/<id>/<N>/master.m3u8
http://<потоковый хост>/vod/<ключ>/S<NN>/<id>/<N>/index<k>.m3u8
```

- `<ключ>` — **тот же ключ портала**, то есть ключ виден в URL потока (в логах и отчётах
  маскировать).
- `S<NN>` — технический сегмент (`S00`, `S30`), `<id>` — номер карточки в хранилище
  провайдера (`00025370`), `<N>` — номер дочернего потока (серия/часть, с 0).
- Хост потока **не совпадает** с хостом портала (портальный отдаёт постеры и JSON,
  потоковый — HLS). В проверенной выборке домен потокового хоста был один и тот же; от
  портала к порталу он может отличаться.

### 5.2 Варианты качества

| Ключ `variants` | Что отдаёт | Разрешение (по меткам карточки) |
|---|---|---|
| `480` | `index1.m3u8` | SD |
| `720` | `index2.m3u8` | HD |
| `1080` | `index3.m3u8` | Full HD (`fhd: true`) |
| `1440` | адрес `indexN.m3u8` (точный номер не проверен: ссылка отдаёт `403`) | QHD (встречался в 10 карточках) |
| `2160` | `index1.m3u8` | 4K (`4k: true`) |
| `auto` | `master.m3u8` | плейлист со всеми вариантами |

Набор неполный и непостоянный: у части 4K-фильмов только `2160`, у архивных — только `480`,
у обычных — `480/720/1080/auto`. В приложении `VodQuality` знает ключи `480`, `720`, `1080`,
`2160`, `auto`, но **не знает `1440`** — вариант отбрасывается при разборе (встречался
у 10 из 111 карточек выборки); отдельного выбора качества в плеере тоже пока нет.

### 5.3 Доступность потока из текущего окружения

**Все проверенные VOD-ссылки отдают `403 Forbidden` с пустым телом**, независимо от:

- фильма (5 карточек), серии сезона, конкретного `indexN`;
- `User-Agent` (нет / okhttp / VLC / ExoPlayer / Chrome), `Referer` (портала, потокового
  хоста, произвольный), `Origin`, `Accept`, `Accept-Language`, cookie, HTTP/1.0;
- `https` — потоковый хост TLS не поддерживает (`wrong version number`).

При этом сам хост жив: отвечает `Server: nginx`, на не-VOD путях (`/`, `/vod/`,
`/nonexistent`) — `curl: (52) Empty reply from server`. Заголовки `403`: `Cache-Control:
private, max-age=0, no-cache`, тело пустое. Похоже на ограничение по IP/сети или на
привязку ссылки к сети абонента — проверка кодаков, HDR и master-плейлиста из этого
окружения невозможна (см. открытые вопросы). Ранняя версия контракта
([edem-vod.md](edem-vod.md)) фиксировала `200` и `application/vnd.apple.mpegurl` — значит,
с тех пор доступ изменился либо запросы шли из другой сети.

### 5.4 Постеры

| Адрес | Размер | Вес | Заголовки |
|---|---|---|---|
| `/posters/h/p_XXXXXXXX.jpg` | JPEG 500×750 | ~50 КБ | `Content-Type: image/jpeg`, `Cache-Control: max-age=2592000`, `Expires` +30 дней, `Last-Modified` |
| `/posters/l/p_XXXXXXXX.jpg` | JPEG 400×600 | ~21 КБ | то же |

Только два размера: `/posters/m/`, `/posters/s/`, `/posters/xl/` → `404`. Постеры
кэшируются 30 дней — клиентскому кэшу есть на что опереться. Обычный `http`, без
авторизации.

### Аудиодорожки и озвучки

Проверено 10.11.2026 живыми запросами и разбором самих потоков:

- в ответе `flick` нет полей про язык, озвучку или аудиодорожки — ключи только `4k`, `agelimit`,
  `description`, `duration`, `fhd`, `fid`, `hdr`, `img`, `imglr`, `pfid`, `title`, `type`, `url`,
  `variants`, `year`;
- в `master.m3u8` нет ни одной строки `#EXT-X-MEDIA`, то есть отдельных аудиопотоков плейлист
  не объявляет;
- `#EXT-X-STREAM-INF` описывает ровно один аудиокодек на вариант (`mp4a.40.2`), атрибут `AUDIO=`
  не используется;
- в плейлисте качества `#EXT-X-MEDIA` тоже нет (встречается только `#EXT-X-MEDIA-SEQUENCE` —
  номер первого сегмента);
- `ffprobe` по скачанному сегменту показывает один аудиопоток: `aac`, 2 канала, без `language`
  и `title` в метаданных.

Вывод: портал и его потоки отдают одну аудиодорожку — выбора озвучки или языка через API нет.
Если провайдер добавит озвучки, они появятся как `#EXT-X-MEDIA:TYPE=AUDIO` в `master.m3u8`,
и тогда выбор можно будет добавить в приложении (сейчас нечего выбирать).

## 6. Ошибки и их причины

| Ответ | HTTP | Причина | Что делать клиенту |
|---|---|---|---|
| `{"type":"error","description":"subscription required"}` | 200 | нет `key`; `key` пустой/`null`/неверный; подписка кончилась; тело не JSON, массив, `{}`, дубликат `key` с плохим первым | считать медиатеку неподключённой, показать просьбу проверить ключ |
| `{"type":"error","description":"illegal command"}` | 200 | неизвестная/неподдерживаемая `cmd`, `cmd` в другом регистре | сбой совместимости; в приложении не должно случаться |
| `{}` (пустой объект) | 200 | `flick` с неизвестным `fid` или с `fid` категории | показать «карточка недоступна» |
| `{"type":"category","items":[],"count":0}` | 200 | `flicks` с неизвестным/строковым/пустым `fid`, либо без `vc` для категорий 10/11 | пустое состояние категории |
| пустое тело | 400 | POST без тела; `Content-Type: text/plain` | ошибка запроса (баг клиента) |
| пустое тело | 405 | `GET`/`HEAD` | только POST |
| HTML «413 Request Entity Too Large» | 413 | тело > 1024 байт | сократить `query` (для `search`) |
| HTML «500 Internal Server Error» | 500 | адрес без завершающего `/` (`/api/v1`) | нормализовать адрес |
| HTML «404 Not Found» | 404 | путь вне `/api/v1/` | — |
| `"items":[,{…}]` (невалидный JSON) | 200 | отрицательный `offset` у `flicks` | не отправлять отрицательный `offset`; парсер не должен падать |

## 7. Ограничения и особенности

### 7.1 Что не работает

1. **Фильтры `controls.filters` полностью нерабочие.** 8+ комбинаций (`years`, `genre`,
   вместе, с `filter: "on"` и без) не меняют ни `count`, ни порядок, ни состав.
2. **Пагинация поиска.** `offset` и `limit` игнорируются, маркера `next` нет, `count` нет:
   доступны только первые ≤500 результатов, «показать ещё» реализовать нечем.
3. **Сортировка каталога.** `sort`, `order`, `by`, `new` игнорируются; порядок только серверный.
4. **Поиск по описанию, id, актёрам, режиссёру.** Ищутся только названия (русское и
   оригинальное), годы — отдельными токенами.
5. **История, избранное, «продолжить просмотр», рекомендации, похожие, жанры, подписка,
   EPG, версия приложения** — команд нет (`illegal command`).
6. **`GET`/`HEAD`** — `405`; только `POST`.

### 7.2 Где сервер ведёт себя неожиданно

1. **Логические ошибки приходят с `200`** — различать только по `type`.
2. **Битый JSON при отрицательном `offset`**: `"items":[,{…}]` — сервер склеивает пустой
   первый элемент и маркер. Парсер обязан пережить.
3. **`flick` без валидного `fid` возвращает чужую карточку** (первый фильм портала), а не ошибку.
4. **`flick` с `fid` категории/несуществующим — `{}`**, то есть пустой объект вместо
   ошибки; при этом `flicks` на тот же `fid` отдаёт пустую категорию.
5. **`fid` строкой (`"1"`) даёт пустую категорию**, хотя JSON формально валиден — типы
   не приводятся.
6. **`vc` обязателен для категорий 10 и 11**: без него сервер молча отдаёт `count: 0`.
   Корень присылает `vc` в `request`, но клиент, собирающий запрос сам, его теряет.
7. **Ограничение тела 1024 байта** — неожиданно маленькое; длинный пользовательский
   запрос в `search` даёт `413` от nginx с HTML-телом.
8. **`Content-Type: text/plain` → `400`**, а отсутствие заголовка (form-urlencoded) —
   работает; проверка заголовка непоследовательная.
9. **`/api/v1` без слэша → `500`**, `/api/v1/anything` → `200` (сверка по префиксу).
10. **Дубликат `key` — побеждает первый**, что не совпадает с поведением большинства
    JSON-парсеров (обычно последний).
11. **Мусор в JSON (`not json`, `[1,2,3]`, `{}`)** трактуется как «нет ключа» →
    `subscription required`, а не `400`.
12. **Несколько постеров одного фильма** в категории 1 и 2 — разные карточки с разными
    `fid` («Одиссея» и «Одиссея (EN)», «Матрица: Воскрешение» и «…4K»); дубликатов по
    названию в выдаче не избежать.
13. **`duration: 0`** у сезонов и у части фильмов — опираться нельзя.
14. **Ключ виден в URL потока** — обязательная маскировка в логах.

### 7.4 Стабильность и приватность API

- API недокументированное и приватное: форма ответа может измениться без предупреждения,
  полей с версией нет.
- Никаких признаков авторизации, кроме `key`: ни сессий, ни подписи, ни срока жизни ссылок
  (URL потока детерминирован и не меняется между запросами).
- CORS открыт (`*`), ограничений по источнику нет.
- Rate limit не обнаружен, но и гарантий нет: 30 запросов подряд прошли.

## 8. Что API позволяет, а приложение пока не использует

Оценка пользы: **высокая** — заметно улучшает клиент, **средняя** — полезно в конкретном
сценарии, **низкая** — приятная мелочь.

| # | Возможность API | Как проверено | Что даёт клиенту | Польза |
|---|---|---|---|---|
| 1 | `vc: 1` в запросе каталога для категорий 10 и 11 | `flicks` `fid=11` без `vc` → `count: 0`; с `vc: 1` → 116 | Сейчас «Сериалы Турции» и «С наступающим!» в приложении всегда пустые: клиент собирает запрос сам и не переносит `vc` из `items[].request`. Починить — одна строка, вернуть два раздела каталога | высокая |
| 2 | `limit` до 300 | `limit=300` → 300 карточек за ~0,3–0,7 с (~330 КБ) | Вместо 10 запросов по 31 на первый экран — 1–2 запроса; меньше задержек и «мигания» автодогрузки | высокая |
| 3 | Готовый `url` у серий внутри сезона | `flick` сезона: `items[].url` заполнен у каждой серии | Можно строить список серий и играть сразу, без `flick` по каждой серии (сейчас детали серии запрашиваются, чтобы получить `variants`) | высокая |

| 5 | `count` каталога | `flicks` → `count: 13121` при странице 30 | Прогресс/«всего N», предсказуемый скроллбар, докачка до конца без лишних запросов | средняя |

| 7 | `duration` в списке | У фильмов секунды (112, 173), у сезонов `0` | Длительность на карточке/в превью без открытия плеера; аккуратно: `0` — неизвестно | средняя |
| 8 | `pfid` (родитель) | `flick` серии → `pfid: 147673` (сезон) | Возврат «к сезону», склейка серий в один сериал, заголовок «Серия N из M» | средняя |

сервер его игнорирует).

## 9. Открытые вопросы

1. **Почему VOD-ссылки отдают `403` из текущего окружения.** Не проверено: привязка к IP
   абонента, к сети провайдера или истёкший токен в пути. Следствие: состав
   `master.m3u8` (`#EXT-X-STREAM-INF`, `RESOLUTION`, `CODECS`, `BANDWIDTH`, `VIDEO-RANGE`),
   кодеки (H.264/HEVC, AAC), HDR, наличие аудио/субтитров, срок жизни ссылки — **сегодня
   не подтверждены**; в [edem-vod.md](edem-vod.md) они записаны по более ранней проверке.
2. **`403` vs `200` по времени.** Ранее (по edem-vod.md) поток отдавался `200` без
   `User-Agent`/`Referer`. Что изменилось — сеть, регион, биллинг — неизвестно.
3. **Смысл `fid` 20, 30, 40** и правила их формирования (подборки? премьеры?) —
   названий и метаданных API не отдаёт.
4. **Признак 18+ на уровне категории.** Категория 9 не приходит в корне, но её элементы
   имеют `agelimit: 18`; отличить «взрослую» категорию от обычной по метаданным корня нельзя.
5. **Точные правила поиска.** Почему `1999` находит 143 записи, а `матрица 1999` — 0;
   почему односимвольные запросы дают ровно 200; почему `the` — 500. Внутренняя модель
   индекса не раскрыта.
6. **Смысл `vc`.** Флаг есть только у двух категорий и только со значением `1`;
   `vc: 2/3` → пусто. Что ещё он переключает — неизвестно.
7. **`duration: 0`** — отсутствие данных или «неизвестно»? Отличить нельзя.
8. **`1440` в `variants`** — какой индекс плейлиста и какое реальное разрешение; сама
   ссылка недоступна из-за `403`.
9. **Есть ли серверный лимит запросов** (rate limit) и как он проявляется — за 30
   последовательных запросов не встретился; поведение при часах нагрузки не проверялось.
10. **Совместимость с другими порталами VPortal.** Схема команд типовая для движка, но
    проверена на одном портале; отличаются ли набор категорий, `vc`, фильтры и лимит
    тела 1024 байта на других — неизвестно.
11. **Актуальность `count`.** Числа меняются (за день: фильмы 13114 → 13121, сериалы
    4842 → 4841), поэтому их нельзя зашивать в тесты.

## 10. Журнал проверок

Все запросы — `POST http://<портал>/api/v1/`, `Content-Type: application/json`, ключ в теле;
