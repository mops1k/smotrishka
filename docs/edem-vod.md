# Медиатека iedem (VPortal): контракт API

Документ фиксирует, как приложение разговаривает с медиатекой провайдера iedem.tv.
Всё описанное проверено живыми запросами 10.11.2026 на личном портале Александра:
`http://<hash>.stremersons.net/api/v1/` (адрес и ключ в репозиторий не попадают).

Расхождения с кодом считаются ошибкой либо документа, либо кода.

## 1. Вход

Пользователь берёт в личном кабинете iedem две вещи:

| Что | Пример | Где хранится |
|---|---|---|
| Адрес портала | `http://<hash>.stremersons.net/api/v1/` | DataStore (не секрет) |
| Ключ портала | `<16 hex>-<16 hex>` | SecretStore, AES-GCM + Keystore |

Пара проверяется корневым запросом (раздел 3): успех — медиатека доступна, ошибка —
медиатека считается неподключённой, пункт меню не показывается.

## 2. Транспорт

- Только `POST` на адрес портала. `GET` отдаёт `405 Method Not Allowed`, пустое тело —
  `400 Bad Request`.
- `Content-Type: application/json`, тело — объект запроса.
- Ответ — JSON, обычно `200` даже для ошибок приложения (см. раздел 7).
- Ключ передаётся **в теле каждого запроса** полем `key`. Клиент подмешивает его
  в любой запрос, включая те, что пришли от сервера в полях `request`.
- Специальных заголовков (`User-Agent`, `Referer`, cookie) не требуется.
- Сервер отдаёт `Access-Control-*` и отвечает на `OPTIONS` — приложение этим не пользуется.

## 3. Корневой запрос

```json
{"key": "<ключ портала>"}
```

Ответ:

```json
{
  "type": "videoportal",
  "url": "http://<hash>.stremersons.net/api/v1/",
  "request": {"key": "<ключ портала>"},
  "items": [{"type": "category", "title": "фильмы",
             "request": {"cmd": "flicks", "fid": 1, "offset": 0, "limit": 0}}],
  "controls": {
    "search": {"request": {"cmd": "search", "query": "{USERINPUT}"}},
    "filters": [{"type": "enum", "title": "Год", "items": [
      {"title": "2021-2026", "request": {"filter": "on", "years": "2021-2026"}}]}]
  }
}
```

Категории (проверено, `count` — размер категории на 10.11.2026):

| `fid` | Название | `count` |
|---|---|---|
| 1 | фильмы | 13114 |
| 2 | сериалы | 4842 |
| 3 | мультфильмы | 1587 |
| 4 | мультсериалы | — |
| 5 | 3D | — |
| 6 | Телепередачи | 1564 |
| 7 | Аниме | 55 |
| 8 | Спорт | 104 |
| 10 | С наступающим! | 0 (пустая) |
| 11 | Сериалы Турции | — |

Порядок категорий — серверный, приложение его не сортирует. Категорию с `count = 0`
показывать не нужно, но пустое состояние экрана обязано быть.

## 4. Каталог категории

Запрос — тот, что пришёл в `items[].request`, плюс `key`:

```json
{"key": "<ключ>", "cmd": "flicks", "fid": 1, "offset": 0, "limit": 31}
```

| Поле | Значение |
|---|---|
| `cmd` | `"flicks"` |
| `fid` | идентификатор категории |
| `offset` | смещение от начала категории, с 0 |
| `limit` | размер страницы; `0` = серверный размер по умолчанию (31 элемент) |

Ответ: `{"type": "category", "items": [...], "count": <всего в категории>}`.

Элемент списка:

```json
{"type": "multistream", "title": "Выстрел",
 "img": "http://<hash>.stremersons.net/posters/h/p_00003949.jpg",
 "imglr": "http://<hash>.stremersons.net/posters/l/p_00003949.jpg",
 "request": {"cmd": "flick", "fid": 147704},
 "fid": 147704, "fhd": true, "4k": false, "hdr": false,
 "year": 2014, "duration": 0, "description": "…", "agelimit": 0}
```

- `type`: `stream` (одиночный поток, в элементе уже есть готовый `url`),
  `multistream` (несколько потоков/серий — нужен `flick`), `next` (маркер страницы).
- `img` — постер большого размера (порядка 250 КБ), `imglr` — превью для сетки.
- `description` и `year` приходят прямо в списке: карточке не нужен отдельный запрос
  только ради описания.
- `duration` в секундах, но у части фильмов приходит `0` — на него нельзя опираться.

### 4.1 Листание

Конец страницы помечен элементом:

```json
{"type": "next", "title": "next", "request": {"offset": 31, "limit": 0}}
```

Клиент берёт базовый запрос (с `cmd` и `fid`) и накладывает на него `request` маркера:
следующая страница = `{"cmd": "flicks", "fid": 1, "offset": 31, "limit": 31}`.
Отсутствие маркера `next` — конец категории (`offset` у конца вернул 4 элемента без маркера).
`limit = 60` работает и возвращает 60 элементов плюс маркер.

## 5. Карточка

```json
{"key": "<ключ>", "cmd": "flick", "fid": 147704}
```

### 5.1 Одиночный поток (`type: "stream"`)

```json
{"type": "stream", "title": "Одиссея (EN)", "fid": 147573, "pfid": 0,
 "variants": {"2160": "http://…/S30/00025355/0/index1.m3u8"},
 "url": "http://…/S30/00025355/0/master.m3u8",
 "year": 2026, "duration": 173, "description": "…", "agelimit": 0}
```

- `url` — HLS `master.m3u8` со всеми вариантами качества внутри;
- `variants` — отдельные `indexN.m3u8` по качествам (480/720/1080/2160) плюс `auto`;
- `pfid` — родительский `fid` (0 у самостоятельного фильма).

### 5.2 Мультипоток (`type: "multistream"`)

```json
{"type": "multistream", "title": "Томми и Таппенс. Сезон 1.",
 "items": [{"type": "stream", "title": "Серия 1", "fid": 147674,
            "request": {"cmd": "flick", "fid": 147674},
            "url": "http://…/S30/00025370/0/master.m3u8",
            "fhd": true, "4k": false, "hdr": false}]}
```

- `items` — серии сериала либо варианты качества одного фильма;
- сезон — **отдельная карточка** в списке категории («… Сезон 1.»), вложенных сезонов нет;
- каждая серия имеет свой `fid` и `url`; деталь серии (`flick` по её `fid`) добавляет
  `variants` и `duration`.

## 6. Поиск

```json
{"key": "<ключ>", "cmd": "search", "query": "матрица", "offset": 0}
```

Ответ: `{"type": "category", "items": [...]}` — те же элементы, что в каталоге,
но **без** `count` и без маркера `next`. `offset` при этом работает: страницы сдвигаются.
Пустой запрос результатов не даёт, поиск чувствителен к регистру только в разумных пределах —
проверено на «матрица» (12+ попаданий) и «star».

## 7. Ошибки

Ошибки приложения приходят кодом `200`:

| Тело ответа | Причина | Что показываем |
|---|---|---|
| `{"type":"error","description":"subscription required"}` | нет `key`, ключ неверный или подписка кончилась | «Подписка медиатеки не найдена — проверьте ключ портала» |
| `{"type":"error","description":"illegal command"}` | неизвестная команда | «Портал не понял запрос» (сбой совместимости) |

Транспортные: `400` на пустое тело, `405` на `GET`, `500` на запрос без `/api/v1/`-пути.
Любой не-HTTP-ответ или битый JSON — ошибка сети/формата, приложение не падает.

## 8. Воспроизведение

- Ссылка VOD: `http://<потоковый хост>/vod/<ключ портала>/S<xx>/<id>/<N>/master.m3u8`.
- Отвечает `200 application/vnd.apple.mpegurl` **без** `User-Agent`/`Referer`; внутри
  `#EXT-X-STREAM-INF` с `RESOLUTION`, `CODECS`, `BANDWIDTH` и ссылками `index-vN-a1.m3u8`.
- `HEAD` не поддерживается (`405`) — проверять доступность только `GET`.
- Кодеки: H.264/HEVC + AAC, встречается HDR (`VIDEO-RANGE=PQ`) и 4K.
- Постеры — обычный JPEG по `http` с хоста портала.
- **Ключ портала виден в URL потока.** В логах и отчётах его маскировать.

## 9. Что не работает и что не проверено

- **Фильтры `controls.filters` бесполезны.** Проверено восемь комбинаций
  (`{"filter":"on","years":"2021-2026"}`, `{"filter":"on","genre":2}` — числовой id из
  `controls`, оба вместе, `filter` объектом, с `limit 0` и `limit 3`, на категории `fid=1`):
  `count` и порядок не меняются. В клиенте фильтры не реализуются.
- История просмотра порталом не отдаётся: позиция и последняя серия ведутся локально.
- `duration = 0` у части фильмов; продолжительность берётся из плеера.
- API приватный и недокументированный: форма ответа может измениться без предупреждения,
  поэтому разбор терпимый — неизвестные поля игнорируются, отсутствующие не роняют экран.
- Сортировка и «похожие» сервером не предлагаются.

## 10. Проверки

- Разбор ответов — юнит-тестами на синтетических фикстурах и `MockWebServer`
  (реальные выгрузки портала в тестах не используются: они меняются).
- Воспроизведение и фокус пульта — только на устройстве.
