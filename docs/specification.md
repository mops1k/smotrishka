# Спецификация SmotrishkaTV v0

Документ фиксирует, что именно делает приложение, по каким правилам, и что считается
готовым. Все пункты — из утверждённых решений интервью; расхождения с кодом считаются
ошибкой либо документа, либо кода.

## 1. Назначение и область

- Личный IPTV-клиент Александра и семьи: 2–3 устройства, установка вручную по APK.
- Не продукт для магазина приложений: без DRM, без политики конфиденциальности, без
  лицензионной поддержки посторонних.
- Один APK на Android TV (управление пультом) и на телефоны/планшеты (касание).
- Контент — линейное телевидение от провайдера: каналы, программа передач, архив.
  VOD-каталог (фильмы/сериалы по запросу) в v0 не входит.

## 2. Термины

| Термин | Значение |
|---|---|
| Источник | способ получить каталог: M3U по ссылке, M3U-файл, код провайдера, Xtream-логин |
| Каталог | категории и каналы, полученные из источника |
| EPG | программа передач (XMLTV) |
| Архив (catchup) | проигрывание прошедшей передачи канала |
| Окно EPG | хранимый диапазон программы: назад — глубина архива из настроек (24 ч … 7 сут), вперёд — 48 ч |

## 3. Источники каталога

Поддерживаются четыре вида, каждый — со своим сценарием ошибок.

### 3.1 M3U по ссылке
- Адрес http/https; плейлист может быть обычным или gzip.
- Кодировка: UTF-8 (с BOM и без), UTF-16 с BOM, cp1251. Определение: BOM → явно; иначе
  строгая проверка UTF-8, при ошибке — windows-1251.
- Разметка: `#EXTM3U` не обязателен; `#EXTINF` с атрибутами в кавычках и без; `group-title`
  или `#EXTGRP`; `tvg-id`, `tvg-name`, `tvg-logo`; `catchup`, `catchup-source`,
  `catchup-days`, `tvg-rec`, `tv_archive`/`tv_archive_duration`; `#EXTVLCOPT` и `#KODIPROP`
  (заголовки потока); `url-tvg`/`x-tvg-url` в заголовке — адрес EPG.
- Относительные адреса потоков разрешаются относительно адреса плейлиста; если базы нет —
  запись пропускается.
- Мусорные строки игнорируются; `#EXTINF` без адреса пропускается; текст, в котором нет
  ни `#EXTM3U`, ни `#EXTINF`, считается ошибкой («не похоже на плейлист»).

### 3.2 Файл M3U с устройства
- Тот же разбор, что и для ссылки; файл читается через Storage Access Framework.
- Статус: слой чтения готов (`PlaylistFileSource`), экран выбора файла — не входит в текущий
  этап, задача заведена отдельно.

### 3.3 Провайдер по коду (iedem.tv)
- Подробное описание механизма — в [iedem-by-code.md](iedem-by-code.md).
- Вход один: код из личного кабинета iedem.tv; никаких CDN-хостов пользователь не вводит.
- Каталог каналов общий и кода не содержит: `http://epg.ottp.eu.org/edem/edem_epg_ico.m3u8`.
  В нём ссылки-заглушки `http://localhost/iptv/00000000000000/<id>/index.m3u8`.
- Настоящая ссылка канала: `http://<хост провайдера>/iptv/<код>/<id>/index.m3u8`; хост зашит
  в профиль провайдера в приложении (как в работающем JS-плеере), код подставляет пользователь.
- Проверено на живом коде: поток отвечает `application/x-mpegURL` и играется; каталог — 3752 канала.
- Валидация: код не пустой, без пробелов и слэшей; неверный код — ошибка без запроса в сеть.
- Программа передач приходит из `x-tvg-url` каталога; архив канала — параметры `?utc=…&lutc=…`
  к ссылке канала (в плеере).
- Хост провайдер может сменить: тогда правится одна константа профиля, код пользователя не меняется.

### 3.4 Xtream Codes
- Вход: `player_api.php?username=…&password=…`; `auth != 1` — неверные данные,
  `status = Expired` — подписка кончилась, не-JSON ответ — неверный адрес сервера.
- Каталог: `action=get_live_categories` и `action=get_live_streams`; архив канала —
  `tv_archive = 1` с глубиной `tv_archive_duration` дней.
- M3U-выдача: `get.php?username=…&password=…&type=m3u_plus&output=m3u8` — разбирается тем же
  парсером, что и обычные плейлисты.
- EPG: `xmltv.php?username=…&password=…`; адрес потока: `<server>/live/<user>/<pass>/<stream_id>.m3u8`.

## 4. Каталог

- Категория: имя провайдера + нормализованный ключ (регистр снят, пробелы → дефис).
  Порядок — как в плейлисте.
- Канал: стабильный ключ (`tvg-id`, иначе `url:<адрес потока>`), имя, адрес потока, логотип,
  категория, идентификатор EPG, параметры архива, заголовки потока (User-Agent/Referer и др.).
- Каталог хранится целиком и заменяется целиком в одной транзакции: смешение двух плейлистов
  на экране недопустимо.

## 5. Программа передач

- Формат: XMLTV (включая gzip); разбор потоковый (SAX), внешние DTD/сущности не загружаются.
- Поток не распаковывается в память целиком: gzip распознаётся по магическим байтам и читается
  на лету. Распакованный EPG крупного провайдера — сотни мегабайт, и попытка прочитать его
  в массив роняет приложение по `OutOfMemoryError` (проверено на реальном файле 49 МБ gzip).
- Окно применяется **во время разбора**: передачи вне «назад — глубина архива, вперёд — 48 ч»
  не попадают в память вовсе.
- Сеть и разбор идут на `Dispatchers.IO`, а не на главном потоке.
- Время: `yyyyMMddHHmmss` и `yyyyMMddHHmm`, смещение `+0300`; без смещения — UTC.
- Читаются `channel/display-name/icon`, `programme/@start/@stop/@channel`, `title`,
  `sub-title`, `desc`, `icon`, `catchup-id`; незнакомые элементы игнорируются.
- Программа без конца, без канала или без названия пропускается; передачи необъявленных
  каналов отбрасываются; порядок «программы раньше объявления канала» допустим.
- Сопоставление с каналами каталога: `tvg-id` → точное имя → нормализованное имя
  (регистр, пробелы, `ё`→`е`). Неоднозначное имя не сопоставляется: лучше «программы нет»,
  чем чужая передача.
- Окно хранения: назад — глубина архива из настроек (варианты 24, 48, 72, 96, 120, 144 и 168 ч,
  по умолчанию 72 ч), вперёд — фиксированные 48 ч; всё за окном удаляется после обновления.
- Окно разбора и окно хранения обязаны совпадать: жёсткие 24 ч назад молча удаляли
  выбранную глубину архива сразу после обновления.
- Провайдер может отдавать архив меньшей глубины, чем выбрано: тогда передач просто меньше.

## 6. Архив (catchup)

- Режимы: `default` (`?utc=&utcend=`), `append` (`/<начало>/<конец>`), `shift`
  (`?timeshift=<минуты>`), `flussonic`/`flussonic-hls` (`index-<начало>-<длительность>.m3u8`,
  для идущей передачи `index-<начало>-now.m3u8`), шаблон `catchup-source` с подстановкой
  `{utc}`, `{start}`, `{utcend}`, `{end}`, `{duration}` (в формах `${имя}` и `{имя}`).
- Незнакомые плейсхолдеры не заменяются — расхождение с провайдером должно быть видно.
- Архив недоступен, если: у канала нет архива; неизвестно начало передачи; передача ещё не
  началась; передача старше глубины архива провайдера; режим неизвестен и шаблона нет.
  В этих случаях UI показывает причину, а не кнопку воспроизведения.
- Конец передачи в будущем обрезается до текущего момента.

## 7. Плеер и OSD

- Звук: у провайдера часть каналов вещает в AC-3/E-AC-3 (проверено: BCU Comedy HD —
  H.264 + две AC-3 5.1 дорожки). Аппаратного декодера AC-3 на телефонах часто нет, поэтому
  в приложение встроен FFmpeg-декодер (`org.jellyfin.media3:media3-ffmpeg-decoder`), а рендереры
  работают в режиме расширений: аппаратный декодер приоритетнее, FFmpeg подключается вместо него.
  Ничего дополнительно скачивать не нужно; APK из-за нативных библиотек вырос примерно до 31 МБ.
- Язык звука настраивается: русская дорожка по умолчанию, можно выбрать английскую или «оригинал»
  (дорога провайдера). Выбор применяется и к уже открытому каналу.
- Полноэкранный Media3/ExoPlayer, HLS; системные панели (статус-строка и навигация) скрыты,
  при выходе возвращаются. Картинка стартует сама, без ручного «играть».
- OSD виден при входе и по касанию/кнопке пульта, гаснет через 4 секунды бездействия;
  повторное касание по пустому месту скрывает его сразу.
- В OSD: название канала, текущая передача и кнопки с иконками — «назад», «−10 с»,
  «пауза/играть», «+10 с», «звук вкл/выкл». Перемотка работает в пределах буфера, в том числе
  на прямом эфире.
- Удержание экрана включённым всё время работы приложения: системный таймаут сна не действует.
- Слабый интернет: обрыв загрузки повторяется до 6 раз; если поток завис в буферизации дольше
  15 секунд, плеер перескакивает на текущий момент эфира и продолжает сам.
- Если поток так и не поднялся, экран пишет «Поток недоступен» и предлагает вернуться к каналам;
  приложение при этом не падает.
- Архив: воспроизведение с начала передачи, повторные попытки и понятные ошибки.
- Планируется (v1): переключение каналов Up/Down и оверлей списка каналов по Left/OK.

## 8. Экраны и управление

| Экран | Содержание | Управление |
|---|---|---|
| Онбординг | выбор типа источника, поля ввода, проверка ввода, прогресс, текст ошибки | пульт (системная клавиатура), касание |
| Главный | две области: слева простой список строк (категории, по нажатию категория заменяется её каналами; «← Категории» или системный «назад» возвращает к категориям); справа живой кадр канала без звука, под ним название, текущая передача, «Далее: …» и «Смотреть». До выбора канала справа «Выберите канал» | пульт: влево/вправо между областями, вверх/вниз по строкам; касание = выбор и запуск; «назад» из списка каналов — к категориям |
| Программа канала | лента передач по времени, прошедшая передача = архив, недоступный архив помечен | пульт, касание |
| Плеер | полноэкранное видео (Media3/ExoPlayer, HLS) без системных панелей; OSD по касанию или OK: название канала, текущая передача, кнопки «Назад», «−10 с», «Пауза/Играть», «+10 с», «Звук»; перемотка доступна только при архиве; OSD гаснет через 4 с; «назад» → список каналов с превью игравшего канала, ещё «назад» → категории | пульт (назад, OK = пауза/играть), касание |
| Настройки | строки «параметр — значение»: источник (с действием «Сменить»), «Буферизация вперёд» (2/5/10/20 с), возврат на главный | пульт, касание, системная кнопка «назад» |

- Приложение работает только в альбомной ориентации (в том числе на телефонах): портретной
  раскладки нет, интерфейс рассчитан на широкий экран. Ориентация закреплена в манифесте
  (`sensorLandscape`) и в `MainActivity`.
- Смена плейлиста открывает онбординг с уже подставленными значениями активного источника;
  сохранение нового источника перезаписывает активный и перезапускает синхронизацию каталога.

- Приоритет пульта: элементы, до которых нельзя добраться пультом, считаются дефектом.
- Экран «Загружаем каналы…» показывается только при запуске, когда показывать ещё нечего.
  Возврат из плеера или с настроек оставляет список на месте; перестройка (запросы программы
  по тысячам каналов) выполняется только если данные действительно обновились.
- Фокус не теряется после переключения категории; выбранная категория и позиция сохраняются
  на время сеанса.
- Канал без логотипа остаётся в списке и показывает заглушку (первая буква названия на плашке
  цвета поверхности) — пустых квадратов в списке и превью быть не должно.
- Каналы без программы остаются в списке с пометкой «Программы нет».

## 9. Слабая сеть

Пользователь может смотреть с очень слабого интернета, поэтому плеер и загрузка данных настроены
на выживание, а не на идеальные условия.

- Поток идёт через OkHttp-датасорс: соединение 20 с, чтение 30 с, повтор при обрыве.
- Неудачная загрузка фрагмента повторяется до 6 раз, прежде чем плеер покажет ошибку.
- Буфер вперёд — из настроек (2/5/10/20 с, по умолчанию 5): короткий обрыв сети перекрывается
  запасом и показ не прерывается.
- Старт с оценкой скорости 800 кбит/с: картинка появляется быстро даже на медленном канале,
  качество плеер поднимает сам, когда сеть позволяет.
- EPG читается потоком и сразу обрезается окном — файл в 49 МБ не загружается в память целиком
  (иначе приложение падало по OOM); таймауты загрузки 20/180 с.
- SAX-фичи отключения внешних сущностей выставляются по одной и с перехватом: Android не знает
  часть фич Xerces, и раньше исключение при выставлении фичи обрывало разбор всей программы
  передач (на экране оставалось «Программы нет»).

## 10. Хранение и безопасность

| Данные | Где | Защита |
|---|---|---|
| Каталог (категории, каналы) | Room `smotrishka.db` | нет (не секрет) |
| Программа передач, каналы EPG | Room `smotrishka.db` | нет |
| Описание источника (тип, адрес, сервер, логин) | Room, таблица `sources` | нет |
| Код iedem.tv, пароль Xtream | DataStore | AES-GCM, ключ в Android Keystore (alias `smotrishka-secrets`) |
| Последний результат обновления | DataStore | нет |
| Логотипы и кадры | дисковый кэш Coil | нет |

- В базе и файлах DataStore не должно быть открытых паролей/кодов: это проверяется тестом.
- Повреждённый шифротекст читается как «секрета нет» (пользователь вводит данные заново),
  приложение не падает.

## 11. Обновление данных

- Триггеры: запуск приложения (разовая задача) и периодическая задача раз в 6 часов;
  обе — только при наличии сети.
- Порядок: плейлист → каталог в базу → EPG → обрезка окна. Сбой EPG не стирает каталог.
- Программа собирается из трёх слоёв: гид провайдера (`url-tvg`/`x-tvg-url` плейлиста),
  затем гиды пользователя из настроек. Гиды пользователя применяются и без адреса у
  плейлиста; недоступный гид не мешает остальным.
- Публичные гиды (проверено 05.11.2026): `epg.one` — тот же бэкенд, что гид провайдера
  (EPG it999), идентификаторы каналов совпадают с каталогом, поэтому идёт первым;
  `epg.it999.ru/edem.xml.gz` — рабочее зеркало; `iptvx.one` — id-слаги, каналы
  сопоставляются по имени. У `epg.one` сломан HTTPS (сертификат истёк 02.11.2026),
  поэтому адрес только `http`.
- Экономия трафика: гид пропускается, если его хост совпадает с хостом уже загруженного
  гида провайдера, если каталог покрыт программой на 95% и более, а также если гид
  успешно скачивали меньше 12 часов назад.
- Пользователь добавляет гид в настройках: адрес проверяется (HTTP-код, формат XMLTV,
  таймаут чтения) и только затем попадает в базу; недоступный адрес не сохраняется,
  причина показывается в строке настроек.
- Результаты: «обновлено» (сколько каналов и передач), «частично» (каталог есть, EPG нет —
  с причиной), «ошибка» (каталог не тронут; воркер повторяет попытку до 3 раз).
- Последний результат сохраняется и показывается в настройках.

## 12. Ошибки: что видит пользователь

- Ввод: «Введите адрес плейлиста», «Адрес должен начинаться с http:// или https://»,
  «Введите код из личного кабинета провайдера», «Код не должен содержать пробелов и слэшей».
- Сеть: «Нет связи с источником: проверьте сеть», «Нет связи с провайдером…».
- Сервер: «Источник ответил кодом N», «Код не подошёл или провайдер недоступен (ответ N)».
- Данные: «Текст не похож на плейлист M3U», «Файл программы передач повреждён…»,
  «Плейлист пуст: проверьте источник и код доступа».
- Архив: причина недоступности вместо кнопки воспроизведения (см. §6).

## 13. Не входит в v0

- VOD-каталог, Xtream VOD API, edem VPortal.
- Несколько источников одновременно, избранное, поиск, история просмотров.
- Превью-ряд в лаунчере Android TV (отдельный этап после приёмки).
- Публикация в магазинах, CI с артефактами, авто-обновление APK.

## 14. Критерии приёмки v0

1. `./gradlew :app:assembleDebug` и все юнит-тесты зелёные.
2. На приставке Android TV: код iedem → каналы видны → канал играет → Up/Down переключает
   в пределах категории → открывается программа канала → вчерашняя передача играет из архива
   без падений.
3. На телефоне: тот же сценарий касанием; интерфейс не обрезан, поля ввода доступны.
4. Обновление данных: после запуска каталог и EPG заполняются; результат виден в настройках.
5. Ошибки источников показываются текстом, приложение не падает при недоступной сети.
6. Отчёт с фактами (что проверено, где, чем) и одобрение Александра.

## 15. Известные риски и допущения

- Живых кодов iedem и Xtream-сервера нет: форматы ответов взяты по документации и референсу;
  расхождения правятся в маппинге без изменения клиентов.
- Формат Flussonic-архива проверен по официальной документации, но не на живой приставке:
  правило «последний сегмент живого URL заменяется на `index-…`» требует подтверждения.
- Фокус-навигация пульта и экранная клавиатура на ТВ проверяются только на устройстве.
- Поведение WorkManager в энергосбережении ТВ-приставки неизвестно до живого прогона.

## 16. Техническая часть: модули и проверки

| Модуль | Назначение |
|---|---|
| `:app` | Активность, навигация, экраны, ViewModel |
| `:core:model` | Доменная модель (`Channel`, `Category`, `Programme`, `PlaylistSource`, `ArchiveInfo`…) |
| `:core:playlist` | Парсеры M3U и XMLTV, декодер кодировок, построитель архивных URL, сопоставление EPG |
| `:core:data` | HTTP-клиенты, Xtream/iedem, Room, DataStore, секреты, обновление и планировщик, Hilt-модули |
| `:core:designsystem` | Тема Compose (Material 3, тёмная палитра) |

Стек: Kotlin, Compose + Material 3, Media3 (плеер), Room, WorkManager, OkHttp, Hilt, Coil;
Gradle 9.8.1, AGP 9.4.1, minSdk 26, targetSdk 36, compileSdk 37. Конвенции: один публичный тип —
один файл, KDoc по-русски, ошибки на границах слоёв — `sealed`-результаты, без `build-logic`.

Проверки:

```bash
./gradlew :core:playlist:testDebugUnitTest  # парсеры, архивные URL, сопоставление EPG
./gradlew :core:data:testDebugUnitTest      # сеть, Room, секреты, обновление, планировщик
./gradlew :app:testDebugUnitTest            # ViewModel'и экранов
./gradlew :app:assembleDebug
```

Тесты идут на JVM; Room и WorkManager — под Robolectric (`@Config(sdk = [34])`), сеть —
`MockWebServer` с синтетическими ответами. Реальные выгрузки провайдеров в тестах
не используются: их формат и данные меняются, и тест на них превращается в ложный сигнал.
